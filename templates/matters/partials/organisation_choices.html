{% comment %} A searchable institution chooser: one text box that narrows one select. The real catalogue runs to hundreds of bodies. A select carrying all of them is unscannable and a wall of radio buttons is worse, so the list is fetched from the server for whatever was typed. No frontend library, no client-side store — HTMX swaps this same fragment back in, which is why the search box and the select live together in one file (Stage-2E.1 brief 13). Without JavaScript the select still holds the currently chosen body plus the first page of the catalogue, and the form still submits — and the term somebody typed reaches the server as an ordinary parameter, so the page comes back with the list they asked for rather than the unsearched first twenty (`app.matters.views._organisation_choosers`). Rendered by the register's Täpsem otsing panel — for **all three** institution dimensions — and re-rendered by `matters:organisation_choices`, so every path produces identical markup over one catalogue. `Saatja` and `Adressaat` used to be plain selects carrying whatever `_organisation_options("")` returned, which is the first twenty bodies alphabetically. Two consequences, and both were reported as "the asutus I just added is not there": a body outside that page could not be chosen at all, and an applied `?saatja=` whose body was outside it was not redisplayed in its own control — so the next submit silently dropped a filter the chip above still claimed was on (docs/adr/0067). `chosen_value` is the raw parameter and `chosen_organisation` the body it names, because they answer different questions: `puudub` names no body and still has to come back selected. {% endcomment %}
