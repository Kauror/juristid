Several production deployments on one day are one group here, because "there were three images that Tuesday" is an operational fact with no reader — what a lawyer wants to know is what was different when they next opened the application. The rows come from docs/release-notes/uuendused.toml, which is where they are edited, in a pull request beside the code they describe. Native `
`/``, not a component. Opening and closing works with no JavaScript at all, the keyboard and the screen reader get the browser's own behaviour, and there is no third accordion implementation in this repository to keep in step with the other two. `.accordion` is the same component the Teema page's sections use, so this page introduces no visual language of its own. The newest day is open and the rest are shut: somebody arriving here almost always wants the most recent change, and a page of thirty open days would bury it. `forloop.first` decides that rather than a flag in the file, so the property cannot go stale as days are added. The heading is written out — «9. september 2026» — and is deliberately *not* a `` element. Every `` on a captured page is masked by the visual suite as clock-derived (e2e/test_ui_regression.py, `CLOCK_DEPENDENT`), and these dates are the opposite of that: they are static content, committed in a file, and painting over them would leave a baseline that no longer shows what the page says. The date is text either way, so nothing a reader or a screen reader receives depends on the element. Every bullet is plain text from a TOML file, rendered through ordinary autoescaping. Nothing here is `|safe`: a release note is prose somebody typed, and a typo in it must not be able to become markup. {% endcomment %} {% block content %}
