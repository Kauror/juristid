{% comment %} The add form for one structured fact, open inside the Matter. `+ Jõustumine` and `+ Töövõit` used to leave the page. The record they write is two or three fields long and the reason for writing it is on the screen the lawyer was just reading, so the trip to a form of its own — and back — was the expensive part of the interaction (docs/adr/0065, superseding ADR 0018's «HTMX fragment swapping for the capture forms»). Nothing about the write moved. The `action` is the same canonical `intelligence:add_*` route, behind the same `business_write_required`, posting to the same service; the fields are `fact_fields.html`, which the standalone page renders too. What changed is that the answer is this fragment rather than a redirect, so a refusal comes back with the values still in the boxes and the errors beside them instead of on another screen. `hx-target` is the whole fact block, which is how one of these is ever open at a time: the server renders the block with at most one `inline_fact`, so opening Töövõit *is* closing Jõustumine. No second state machine, and no state written anywhere to hold it (Teema redesign §D). `method`/`action` are real, so the form still posts without HTMX — it lands on the standalone page's own POST branch, which redirects back to the section anchor exactly as it always did. {% endcomment %}
